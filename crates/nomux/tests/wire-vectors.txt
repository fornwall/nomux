# The frame table of IMPLEMENTATION.md § 2.2 in bytes, for an implementation in another
# language to check itself against: build each record's message from the field values,
# encode it, and the result must be `bytes` exactly; decode `bytes` and the fields must
# come back. Nothing here was produced by the encoder under test — these are the
# document's bytes, not this codec's, which is what makes them a check on it.
#
# Written by hand from § 2.2, not rendered from anything: the `vectors` module of
# `crates/nomux/tests/codec.rs` holds the same table as Rust literals read out of § 2.2 the
# same way, parses this file, and fails if the two disagree — so a wire change has to be
# made twice, in two notations, and a slip in either is caught by the other. It parses
# strictly: an unknown key, a record with no `bytes`, a number written to the wrong width
# each fail, a reader that stepped over what it did not understand being one that would
# retire this file a line at a time.
#
# Grammar, so a reader needs no library: a line is blank, a comment — `#` its first
# non-blank character — or a key and a value separated by whitespace. `frame` opens a
# record and names the message; the keys under it are that message's fields in § 2.2's
# order; `bytes` closes it with the whole frame, four-byte header included. A value is
# `true` or `false`, an enumerator whose number § 2.2 gives, or lowercase hex behind an
# `0x` prefix — a number, zero-padded to the width of its field, except in `term`,
# `message`, `data` and `bytes`, where it is the field's bytes and may be `0x` alone.
# `status` is the one signed field on this wire and is written in decimal, a
# two's-complement pattern being a reinterpretation this file should not ask for.
